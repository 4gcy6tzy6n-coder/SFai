# 研究汇报：Decide-Act —— 可审计的 Agent 运行时与"假成功"基准

**汇报日期:** 2026-11-17 · **项目:** System for future ai（sfai）· **状态:** 实验冻结（36 个结果文件校验封版），论文框架就绪
**仓库:** https://github.com/4gcy6tzy6n-coder/SFai · **产品:** macOS 桌面 App + CLI + HTTP API（v0.3.3 已发布）

---

## 一、一句话故事

Agent 框架都报告"任务完成"——**但谁验证交付物是真的对的？** 我们构建了 Rust 运行时 sfai（核心是模型自路由循环 **Decide-Act**），并提出一个衡量框架仪表盘漏掉的指标——**假成功（false success）：状态"完成"但交付物错误的运行**。在 **18 个模型 × 4 个框架 + 3 个公开基准**上的实证：

> **有验证门：假成功 0.000（72/72 格零例外）｜无验证门：平均 0.324（最高 1.00）**
> 公开基准（HumanEval）上最强烈对照：**无门 0.80 vs 有门 0.00**

---

## 二、系统与方法（四个支柱）

### 1. Decide-Act 内核（核心创新）
- 每步一个 **decide**（模型从 9 类动作意图中选一个）+ 一个 **act**（运行时按策略执行）
- 运行时保障：策略分级（读/可逆写/外部写/高影响）、审批收据、幂等键、循环守卫（同动作×3 无状态变化即拒绝）、路由遥测
- **三层记忆 Index / Wiki / Way**：Way 层记每任务的"方法/优点/**出错重点**"，AI 自写自记（对齐 Claude Code 记忆架构并扩展）

### 2. 验证门（消除假成功）
- 运行时强制验收（工件存在/引用可解析/JSON 合法/答案匹配/测试通过/无占位符），有界修复；算错就阻塞，**宁可如实报失败也不谎报成功**
- 门精度矩阵：捕获 **1.00** / 误杀 **0.00**（零误杀）

### 3. 稀疏上下文激活（成本不随规模涨）
- 预算化工作集（固定约束不驱逐、依赖一致、检索回执）
- **同质量 1/78 token**（160 文档历史：41 tok 恒定 vs 810→3210 tok 线性涨）

### 4. Rust 内核（系统优势）
- 单二进制、事件账本（SQLite WAL）、崩溃恢复、内容寻址
- **16 路并发 CPU 扩展 5.1×（Python 线程 1.0×，GIL 实证）**；内存 2.6× 优；冷启动 255×–378× 优

## 三、核心数据（全部冻结，可复现）

### 表 1｜18 模型主表（聚合，72 格）

| 配置 | 假成功（均值） | 说明 |
|---|---|---|
| **有验证门** | **0.000** | 72/72 格全绿，零例外 |
| 无验证门 | 0.324 | 最高 1.00（deepseek-v4-pro / qwen3.7-max 多格） |

模型家族：DeepSeek-chat、MiMo-v2.6-pro、百炼 16 文本模型（Qwen 3.6/3.7/3.8/4-max、GLM-5.2/5.3、DeepSeek-v4 系、auto、decision-model-preview）。
无门失败模式互补：DeepSeek 抗捏造但算术弱、MiMo/Qwen 算得准但爱编引用——**门对所有失败模式都有效**。

### 表 2｜公开基准（真实迁移，D&B 硬要求达成）

| 套件 | 来源 | 无验证门 | 有验证门 |
|---|---|---|---|
| **HumanEval**（20 题，官方测试为裁判） | OpenAI，MIT | success 0.80 / correct 0.00 / **假成功 0.80** 🔴 | success 0.00 / correct 0.00 / **假成功 0.00** ✓ |
| **GSM8K**（20 题整数子集） | OpenAI，MIT | cor 0.70 / **假成功 0.15** | cor 0.95 / **假成功 0.00** |
| SpreadsheetBench-sheets（20 题） | NeurIPS'24，CC-BY-SA-4.0 | 0.15/0.15/0.00 | 0.15/0.15/0.00（门中性） |

> HumanEval 的解读：无门时框架自信报告 80%"完成"，**代码根本过不了测试**；有门时全部被如实拦下——这正是"假成功"问题的最强实证。

### 表 3｜假成功 CI 收紧（n=16）与门精度

| 指标 | 无验证门 | 有验证门 |
|---|---|---|
| 假成功（Wilson 95% CI） | **0.38 [0.18, 0.61]** | **0.00 [0.00, 0.19]**（CI 不相交） |
| 门捕获率（拦截错交付） | — | **1.00** |
| 门误杀率（误拦对交付） | — | **0.00** |

**自路由真实行为**：捏造压力下 ask_user 率 **0.94**（模型拒绝编造引用、反问用户）——Decide-Act 的"模型自路由"被真实使用。

### 表 4｜稀疏激活成本曲线（E5 sweep）

| 文档规模 | working_set（我们的） | full_history |
|---|---|---|
| 40 docs | 41 tok | 810 tok |
| 80 docs | 41 tok | 1620 tok |
| 160 docs | **41 tok（恒定）** | **3210 tok（78×）** |

质量持平（正确率同、约束保真 1.00 vs 0.00 衰减）；top-k 消融：k=2 于 160 文档翻车 → 32 处 target 权重锚定。

### 表 5｜Decide-Act 消融（自路由 vs 固定管线，n=4）

| 任务类型 | 自路由 | 固定管线 | 结论 |
|---|---|---|---|
| long-horizon（检索密集） | **1.00** | **0.00** | 自路由决定性（固定检索路线全灭） |
| dataset（流程化计算） | 0.25 | **0.75** | 固定管线更优（自路由开销） |
| tool-use | 1.00（19k tok） | 1.00（**5k tok**） | 平，自路由 4× 成本 |

**诚实双向结论：「适应性换开销」**——流程固定时固定管线赢效率，任务不确定时只有自路由能完成。定位主张：route when uncertain, pipeline when certain（future work：混合路由）。

### 表 6｜跨框架对比（同模型 deepseek-chat、同判分器、n=6）

| 框架 | dataset 假成功 | tool-use 假成功 | p50 |
|---|---|---|---|
| LangGraph ReAct | **0.50** 🔴 | 0.00 | 2.2s |
| smolagents | 0.00 | 0.00 | 5.5s |
| Pydantic AI | 0.00 | 0.00 | 3.9s |
| **sfai** | **0.00** | **0.00** | 7.6s |

**诚实解读**：修正判分器后框架差距收窄；差异在**错误处理**——同模型算错时无验证层框架静默交付（LangGraph 0.50），sfai 门拦截（0.00）。sfai 的成本是验证/修复轮 + 自路由轨迹（表 5 量化）。大样本佐证见表 1。

## 四、数据可信度（如实披露，附录级）

1. **判分器三次事故与修正**：键名强校验 → 值匹配 → 数值比较 → 文件名无关+任务间清理；所有作废版本不入表（Debug 报告 #13）
2. **E9 网络事故**：HumanEval 两轮（27 超时 + 37 DNS 失败）作废归档后改百炼补测完成（Debug 报告 #14）
3. **并发扫描延迟噪声**：跨模型延迟对比仅供参考；成功率/正确率/token 不受影响
4. **样本量**：n=2–16/cell（Wilson CI 全表给出）；订阅制计价（比 token 不比美元）；合成+公开混合任务
5. **E8 双向结果如实呈现**（不主张自路由处处更优）
